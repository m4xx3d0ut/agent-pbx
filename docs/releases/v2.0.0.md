# Agent PBX 2.0.0

Agent PBX 2.0 changes the product boundary from a terminal-reporting TUI into a
durable control plane for Codex runtimes. Agent and Operator identity,
workspaces, policy, routing, campaigns, approvals, audit, and lifecycle remain
PBX-owned. Codex owns the reasoning and execution loop inside each root
session, including bounded child-agent decomposition.

## Native tmux workspace

The v1 left/right layout and complete right-side tab bar remain. `Latest` can
now host a PTY-backed normal tmux client connected to a PBX-managed runtime, so
Codex selectors, warnings, approvals, paste, mouse, resize, cursor state, and
tmux scrollback behave like a native terminal inside the TUI.

Local clients default to native tmux plus the v2 event stream. The committed
runtime-server default is `dedicated`; private workstation configurations can
select `outer_if_present` for targeted same-server pop in/out over local or SSH
tmux clients. Plain F keys remain PBX navigation. Shift+F1–F12, including
Shift+F2, translates to child F1–F12 so Codex warnings remain reachable.

## Codex harness and models

- Adds versioned Codex capability, model, feature, and protocol probes.
- Binds state to proven PBX/Codex/tmux session identity and records evidence
  provenance instead of treating rendered text as authoritative.
- Preserves `/copy → transcript → tmux capture` with session, file, phase,
  line, and mtime provenance plus turn-boundary safeguards.
- Generates catalog-validated profiles and supports safe restart/resume model
  transitions.
- Ships Sol 5.6/xhigh/high/detailed as the standard engineering profile,
  retains Terra alternatives, and treats Sol max as a bounded, justified,
  user-approved elevation.
- Adds the generic Roses Architect skill profile and private local personality
  overlays; the workstation overlay may identify Rosie-0, known simply as
  Rosie, without entering Git or shared diagnostics.

## Control-plane and UI changes

- Adds sequenced event snapshots, bounded replay/resync, authenticated
  WebSocket clients, and independent remote view state.
- Adds a unified runtime/lifecycle service for Agents, Operators, edit forks,
  and review forks, including mapping repair, migration preview, prune guards,
  and undo.
- Adds observed Codex child topology under its owning PBX entity.
- Adds typed actions, focus-generation guards, cancellable jobs, and stale
  result protection to prevent cursor snap and event-loop stalls.
- Adds deuteranopia-friendly semantic theming for PBX, tmux, and Codex syntax
  surfaces.

## Joplin and Editor

- Joplin now opens in rendered Markdown read mode and uses explicit edit mode.
- Optimistic revisions, three-way review data, conflict copies, and durable
  sync jobs prevent silent lost updates.
- Editor CRUD uses the existing path/symlink/sensitive-file boundary.
- Untracked deletes move to a project-local recoverable trash manifest;
  tracked deletes remain visible to Git.

## Remote and security posture

- Adds expiring, revocable, role/scoped remote credentials, WSS replay/resync,
  rate limits, bounded queues, and audited controller actions.
- SSH attach remains the full-fidelity remote terminal path.
- LAN listeners require token plus TLS unless the operator explicitly enables
  the controlled lab override.
- Provider secrets, auth material, hidden configuration, private overlay text,
  terminal history, and hidden reasoning stay out of shared event payloads.

## Installation and migration

Read [the v2 installation guide](../install-v2.md) before upgrading a running
daemon. The release includes doctor, backup, dry-run, apply, verify, and
rollback commands; checksummed offline wheelhouses; dependency manifests; and
an SPDX 2.3 SBOM.

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
agent-pbx mcp stop
agent-pbx migrate apply
agent-pbx migrate verify
agent-pbx mcp start
```

For a LAN daemon, configure TLS before starting v2. Rollback restores verified
database and optional local-config artifacts while preserving newer project
files, Joplin notes, Codex transcripts, and trash entries.

## Compatibility

Polling/nohup mode, Thread, HTTP refresh, and terminal capture remain supported
through the v2.0 line. They are explicit machine-readable compatibility paths
and remain enabled by default. Native tmux and WebSocket events are preferred
for local clients. See [the acceptance record](../acceptance/v2-uat.md) for
checkpoint, test, packaging, security, and host-migration evidence.

The final release candidate passed the checksummed wheelhouse gate and the full
793-test suite on Ubuntu and macOS with Python 3.10 and 3.12 in
[GitHub Actions run 37098170906](https://github.com/m4xx3d0ut/agent-pbx/actions/runs/37098170906).

The final Python 3.10 offline archive contains 51 wheels and installs
`agent-pbx 2.0.0` into a clean environment without network access. Its SHA-256
is `a264c8004ef9a3eb00d453169447fac6731a9f02adcd0cde0ba07fa02d04b3fb`.
