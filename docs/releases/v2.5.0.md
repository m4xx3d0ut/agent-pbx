# Agent PBX 2.5.0

Agent PBX 2.5.0 is the stable release of the runtime-reconciliation and
component-boundary cycle qualified through `v2.5.0rc4`. It retains the v2.4
durable engineering control plane while making its live Codex, tmux,
WorkerBee, campaign, and TUI evidence more exact, explainable, portable, and
maintainable.

The stable identity is derived from the exact RC4 product tree by version and
release documentation only. RC4 passed the full Linux/macOS and Python
3.10/3.12 matrix, TestPyPI Trusted Publishing, registry-hash verification,
clean installation, and managed workstation activation before stable
preparation.

## Component boundaries and compatibility contracts

The v2.5 cycle continues the post-v2.4 decomposition without changing public
behavior merely to move code. API route families, Textual screens and
controllers, persistence repositories, WorkerBee metadata/projection services,
and restart preparation now have explicit owners and dependency direction.

Executable checks freeze:

- the public OpenAPI and route inventory;
- Store declarations, schema fingerprint, and reviewed atomic operations;
- TUI widgets, tabs, bindings, actions, and terminal-focus ownership;
- import direction and internal cycle freedom; and
- growth ceilings for the remaining central modules and extracted components.

The TUI method identity checker normalizes only empty interpreter-version AST
fields, so identical source has one compatibility identity on supported Python
versions without accepting actual action or keymap drift.

## WorkerBee profile and tool reconciliation

WorkerBee authority remains independent from Codex model, filesystem, Git,
broker, provider, deployment, publication, and credential authority. Managed
launch and restart paths now derive their inventory from the effective access
profile and reconcile durable intent with the current backend generation and
gateway lease immediately before restart.

Platform-appliance discovery is classified into stable profile projections.
Cloud/platform tools are available only through profiles that allow their
classified capability, while broad execution such as `workerbee_v1_exec`
remains limited to the trusted-workbench boundary. A stale lease is replaced;
an elevated profile is never inferred.

## Exact runtime interaction

Terminal delivery treats durable reports as workflow history rather than live
authorization. Before injecting input, Agent PBX proves the exact entity,
Codex session, tmux socket/session/window/pane, process identity, workspace,
authority evidence, input composer, overlay state, and writer lease. It then
rechecks identity and readiness after acquiring the lease.

This permits a new, authorized assignment to reach an input-ready retained
runtime even when its earlier report is terminal, without reopening or
rewriting history. Explicit outcomes distinguish delivery, queueing,
not-ready, overlay, ambiguity, policy block, and stale mappings.

## Managed TUI and tmux resilience

The production TUI entrypoint records exact host-terminal identity and watches
that parent while the client owns a writer lease. If the outer terminal
disappears or changes, Agent PBX releases only that disposable client's lease
and exits the orphan client after a bounded grace period. It does not stop,
signal, restart, move, join, remap, or replace the managed Codex pane.

Restarted panes refresh PID and process-start evidence before later readiness
checks. Recursive TUI launch into a managed runtime fails closed unless the
explicitly isolated web-demo stdio boundary is in use. On systems without
Linux `/proc` start ticks, run-marker cleanup uses a non-signalling PID
liveness probe and conservatively preserves evidence for another live client.

## Caller recovery and campaign topology

A durable caller without a managed runtime can be recovered through a
preview-token-bound transaction. The operation validates project and profile
policy, confirms that no current mapping or conflicting session exists, starts
a fresh independent Codex session, atomically binds it to the existing PBX
identity, and removes only the disposable new runtime if persistence fails.
Historical session IDs are warning evidence and are never resumed implicitly.

Campaign assignments now persist their delivery topology. `operator_fork`
remains the compatible default. A root Operator may explicitly select
`direct_caller` for an existing caller, using the same exact runtime delivery
contract. Follow-ups inherit the assignment topology and cannot switch it.

After dispatch and follow-up, all-terminal assignments reconcile the campaign
to terminal state. Completion receipts, approvals, failed deliveries, and
other durable review work remain independent and visible until resolved.

## Codex child and MCP inventory observability

Observed Codex child records retain PBX correlation metadata and, where
available, native Codex child identifiers. Availability and stale detection
remain separate from durable completion state, preventing an old process
observation from erasing a valid terminal result.

Agent PBX also records a deterministic manifest digest for the exposed MCP tool
contract. New launches carry that digest, and the TUI can distinguish current,
stale, unknown legacy, no-runtime, and unavailable inventories. This evidence
does not grant a tool, widen policy, or automatically restart a session.

## Compatibility and migration

The additive SQLite schema advances from 45 to 46 for persisted campaign
delivery topology. Existing Agents, Operators, forks, stars, reports,
campaigns, handoffs, Codex sessions, tmux mappings, writer leases, projects,
knowledge, helpers, and audit records are preserved. Existing assignments
migrate to `operator_fork`.

Before upgrading a long-lived control plane:

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
agent-pbx mcp stop
agent-pbx migrate apply --retention-days 7
agent-pbx migrate verify
agent-pbx mcp start
agent-pbx doctor
```

Do not restart the managed tmux server or healthy Codex processes solely for
this upgrade. Restart the daemon and connected TUI clients so they load the new
package. Restart individual Codex sessions at reviewed turn boundaries only
when they need the current MCP inventory or WorkerBee launch projection.

```bash
python -m pip install agent-pbx==2.5.0
agent-pbx --version
agent-pbx doctor
```
