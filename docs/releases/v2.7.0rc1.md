# Agent PBX 2.7.0rc1

This release candidate moves WorkerBee backend selection and recovery into the
Agent PBX daemon. It also clarifies the distinction between the Codex launch
profile shown by Doctor and the model observed in a running session.

## Select and verify a backend

The daemon imports an exact valid legacy selection into a private selector
database. It retains the backend instance and generation and leaves the
original selection as migration evidence. The application database remains at
schema 46.

A global controller previews a switch against the current generation. The
daemon binds the preview to the qualified adapter's artifact, effective
configuration, route and transport, then closes admission and drains pending
work before changing the backend. Publication advances the generation once.
A verified rollback advances it again, requiring older sessions to rebind.

The WorkerBee tab and Doctor distinguish committed selection from observed
evidence. While a cutover is held, they can show the selected identity and
recovery state without initiating a probe, issuing a lease or rebinding a
workspace. If exact recovery readback is unavailable, admission stays closed.

## Adapter availability

The standard daemon starts with the legacy adapter for backend discovery and
existing bindings. In that configuration, Agent PBX denies effectful switch
previews. The provider-free test harness supplies a qualified adapter and
checks all six ordered directions across OSS, platform debug, and a synthetic
user appliance. Live cutover requires a host adapter with verified artifact,
route, configuration, and transport evidence. Qualification of a deployed
user appliance remains separate.

## Upgrade and recovery

Before an approved activation, record the current backend identity and preserve
the legacy selection, application database and any existing selector journal.
Keep the selector journal when investigating or recovering an interrupted
switch. Restoring older selection state after a cutover can invalidate
generation-based lease isolation.

See [WorkerBee Integration](../wiki/WorkerBee-Integration.md) for selector
readback, session binding and recovery guidance, and the
[release procedure](../releasing.md) for packaging and publication.
