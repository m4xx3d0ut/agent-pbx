# Agent PBX 2.7.0rc2

This release candidate retains the durable WorkerBee selector and fixes a
Codex model catalog issue on newly booted hosts.

## Codex catalog startup

The runtime used zero as the timestamp for a catalog it had never loaded.
When monotonic uptime was five minutes or less, the first lookup treated the
empty cache as fresh. This could mark an available managed or catalog model
as stale, preventing adoption even with valid session evidence.

The first lookup now loads the catalog immediately. Subsequent lookups keep
the existing refresh interval. Provider identity, catalog support, and
elevation lease requirements still apply.

## WorkerBee and manual validation

The selector behavior and application database schema 46 carry forward from
the [RC1 release notes](v2.7.0rc1.md). The standard daemon uses the legacy
adapter for WorkerBee discovery and existing bindings. Effectful backend
cutover requires a qualified host adapter.

Check catalog readback and adoption after an isolated daemon start. For
workstation UAT, record live runtime mappings and the WorkerBee selection
before changing the daemon and TUI. Keep the previous application database
and selector evidence available for rollback. See the
[installation and rollback guide](../install-v2.md) and the
[release procedure](../releasing.md).
