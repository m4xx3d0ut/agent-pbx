# Agent PBX 2.3.0rc4

Agent PBX 2.3.0rc4 is the final release candidate for the v2.3 control-plane,
Operator-workflow, WorkerBee-policy, and runtime-resilience cycle. It preserves
the complete RC3 product tree and closes two cross-platform qualification gaps
found before any RC3 artifact reached TestPyPI.

Production users should continue to use Agent PBX 2.2.0 until this candidate
passes reviewed workstation activation and is promoted as 2.3.0.

## Changes since RC3

- Trusted-direct-bind tests now use deterministic private-primary-group
  evidence on Linux and macOS. Production admission still resolves the real
  daemon account database and fails closed when the writable primary group is
  shared or cannot be proven.
- The F8 single-flight approval test now supplies complete Agent API records.
  This removes a timing-dependent background-render failure without changing
  the TUI action, alert, or approval behavior.

The immutable RC3 tag is retained as an audit point. Its TestPyPI workflow
stopped in quality validation, before OIDC publication, so no RC3 distribution
was uploaded to the registry.

## Qualification and activation

Repository qualification uses temporary databases, disposable tmux servers,
isolated Git repositories, fixture WorkerBee endpoints, and clean package
environments. It does not restart the workstation daemon or TUI, switch a
WorkerBee backend, signal a managed Codex process, or alter a live runtime
mapping.

Before workstation activation:

1. record the exact RC4 commit and registry hashes;
2. back up the database, configuration, runtime mappings, and package identity;
3. run migration dry-run and integrity verification;
4. restart the daemon without restarting the managed tmux server;
5. launch the TUI through the reviewed local wrapper;
6. verify retained Agents, Operators, forks, panes, Codex sessions, Joplin,
   WorkerBee, model policy, and managed editor state;
7. restore the matching backup and prior package if any check fails.

Running Codex processes do not inherit a newly installed CLI binary. Existing
sessions remain intact until an explicit safe-boundary restart/resume. New
launches and later resumes use the qualified host executable recorded by Agent
PBX.

## Promotion

This candidate is eligible for 2.3.0 only after the exact GitHub/TestPyPI
artifacts pass the release matrix, clean installation, reviewed workstation
activation, and representative Agent/Operator/Joplin/native-terminal smoke.
Stable promotion should change release identity and documentation only. Any
semantic runtime change requires another release candidate.
