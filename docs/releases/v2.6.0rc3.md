# Agent PBX 2.6.0rc3

Agent PBX 2.6.0rc3 is the final compatibility candidate for the Codex 6.2
model-policy cycle. It retains the complete RC2 provider, live-catalog,
adoption, and elevation hardening while correcting one TUI comparison at the
retained Sol 5.6 migration boundary.

## Retained elevation lease compatibility

The API has always normalized historical Sol elevation names such as
`sol-max` to the canonical `sol-5.6-max` profile before returning a new lease.
The TUI intentionally retains the historical alias while representing an
existing Sol 5.6 preset. RC2 compared those two strings literally when an
approved lease was prepared or activated.

RC3 compares the canonical managed profile identities instead. Consequently:

- a canonical API lease matches the retained Sol 5.6 preset;
- historical leases and current canonical leases share one elevation identity;
- approval, activation, same-thread resume, and rollback remain available for
  migration-only Sol 5.6 sessions; and
- unrelated, unknown, or non-elevated profile identifiers continue to fail
  the exact-match checks.

The correction does not make Sol 5.6 eligible for a new role default or normal
launch. It does not change the direct Codex `/model` picker, the Codex 6.2
policy matrix, the database schema, WorkerBee access policy, or managed tmux
session topology.

## Model policy

The committed defaults remain:

| Surface | Committed profile |
| --- | --- |
| Caller Agent | `sol-6.2-medium` |
| Root Operator | `sol-6.2-high` |
| Edit fork | `sol-6.2-high` |
| Review fork | `sol-6.2-high` |
| Efficient task | `luna-6-high` |
| Visual task | `terra-6.1-high` |

Owner-local trusted-workstation overrides remain outside Git. Stars continue
to control lifecycle and retention only; they do not select a model.

## Upgrade and rollback

RC3 does not change schema 46. Upgrade by restarting only the Agent PBX daemon
and TUI at a reviewed activation boundary. Healthy managed tmux servers, Codex
processes, thread IDs, WorkerBee leases, and project mappings remain in place.

Rollback restores the previous package and restarts the daemon and TUI. No
runtime mapping or persisted data migration is required.

## Qualification boundary

Before stable promotion, RC3 must pass focused model/elevation tests, the full
parallel-safe and isolated serial pytest lanes, repository compatibility and
documentation guards, and isolated wheel/source-distribution validation. A
tracked acceptance record must identify the exact qualified source and package
hashes.

This candidate may be activated locally for manual review, but it must not be
tagged, pushed, published, or promoted to stable `2.6.0` without the separate
publication approval.

## Install the candidate

After an explicitly approved TestPyPI publication:

```bash
python -m pip install --index-url https://test.pypi.org/simple/ \
  --extra-index-url https://pypi.org/simple/ \
  agent-pbx==2.6.0rc3
```
