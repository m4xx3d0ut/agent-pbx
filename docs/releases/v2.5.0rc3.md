# Agent PBX 2.5.0rc3

Agent PBX 2.5.0rc3 is a narrow release-candidate correction to the v2.5
runtime presentation and TUI host-liveness boundary. It preserves the complete
RC2 terminal-delivery, component-decomposition, WorkerBee, Git broker, and
managed-runtime contracts.

The candidate does not advance the database schema. Schema 45, public routes,
OpenAPI structure, Store signatures, transaction boundaries, feature defaults,
managed tmux mappings, and migration behavior remain unchanged.

## Production TUI host-liveness entrypoint

RC2 introduced exact host-terminal identity and a watchdog that prevents a
disconnected interactive TUI from retaining or reacquiring the embedded
terminal writer lease. RC3 corrects the production launch path so the recorded
TUI entrypoint uses that watchdog as well as the direct compatibility
entrypoint.

If the exact launch parent or terminal disappears or changes, Agent PBX:

1. marks that disposable TUI client as host-liveness lost;
2. releases only the writer lease held by its exact client ID;
3. requests graceful TUI termination; and
4. forces the orphan client to exit after a bounded grace period if its event
   loop cannot complete shutdown.

The watchdog never stops, signals, restarts, moves, joins, remaps, or replaces
the managed tmux pane or Codex process. Noninteractive pilot and test launches
remain outside the production-only guard.

## Truthful Codex child availability

The PBX runtime projection now keeps two independent facts for each observed
Codex child:

- **lifecycle history**, such as the last known thinking, executing, or
  complete state; and
- **current discovery availability**, such as active, idle, unloaded, or
  discovery error, with a bounded freshness timestamp.

This prevents historical children returned as `notLoaded` from appearing as
currently active merely because their last lifecycle event was thinking. A
confirmed active child must have an active lifecycle, current active
availability, and a successful observation within the freshness window. If
the app-server bridge stops refreshing it, the child fails closed to stale.
Unchanged discovery heartbeats update only the in-memory freshness projection
and do not create repetitive audit-journal events.

The right-pane topology distinguishes active, stale, and terminal totals and
orders confirmed-active children first. Stale rows retain useful bounded
context such as `UNLOADED · last THINKING` without claiming current work.

## Correlation with native Codex `/subagents`

When Codex supplies them, Agent PBX now preserves the public child nickname and
spawn depth. The topology label uses the nickname plus an abbreviated thread
ID, allowing an operator to correlate the PBX row with the native Codex
`/subagents` palette without exposing prompts, transcript paths, private agent
configuration paths, or hidden reasoning.

This is a correlation aid, not a merged control surface. RC3 does not add
child steering, selection, cancellation, policy editing, custom-profile
verification, usage metrics, or association repair.

## Deferred v2.6.0 scope

The following broader work remains intentionally outside the v2.5 release:

- an interactive child inspector and cross-surface selection;
- explicit child model, reasoning, profile, concurrency, and authority policy;
- token, duration, tool, and peak-parallelism metrics;
- stronger association diagnostics and guarded repair;
- event timelines and long-run retention controls; and
- clearer native/PBX topology ownership in settings and documentation.

Those features require separate contracts and qualification rather than a late
expansion of the v2.5 release candidate.

## Compatibility and security

Existing persisted child projections remain readable because all new fields
are optional. Historical snapshots without availability evidence render as
stale rather than active. No existing Agent, Operator, fork, campaign, handoff,
runtime mapping, writer lease, or Codex session is rewritten by installation.

The candidate does not change model defaults, native Codex subagent limits,
custom agent declarations, Git or broker authority, WorkerBee access, provider
or credential access, review-fork policy, publication rights, or remote-client
permissions. It records no prompt bodies, terminal text, transcript paths,
private agent paths, or hidden reasoning in the new projection fields.

## Qualification boundary

Qualification uses isolated stores, fake app-server responses, disposable TUI
objects, and mocked lease-release requests. It verifies:

- production entrypoint coverage for the host watchdog;
- exact writer-lease release and bounded orphan termination;
- active, unloaded, stale, error, and terminal child presentation;
- current discovery heartbeats without journal churn;
- nickname and spawn-depth correlation;
- rejection of private prompt, reasoning, transcript, and agent-path fields;
- component ownership and compatibility contracts; and
- unchanged runtime/session behavior outside this correction.

No live managed pane, Codex process, tmux server, runtime mapping, writer lease,
daemon, or TUI is used by these tests.

The bounded local release runner completed on the candidate source with:

- **2,018 passed** and **2 expected opt-in skips** in the four-worker
  parallel-safe lane; and
- **3 passed**, **1 expected opt-in skip**, and **2,020 deselected** in the
  isolated serial lane.

Ruff on every changed Python path, Python compilation, `git diff --check`, the
documentation validator, component ownership/no-growth checks, README checks,
release validation, release packaging, and the focused Codex/TUI/runtime lanes
also passed. The candidate-owned failure count is zero.

## Upgrade and rollback

Run the normal doctor and migration dry-run before a separately reviewed local
activation. The expected schema-45 result is `changes_required=false`:

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
```

The immediate source rollback parent is RC2 follow-up commit
`6ee2ecb685285dd09323ae3b1b52b07fcf48fbea`. Selecting that parent removes the
production watchdog-entrypoint correction and child-availability projection
without changing schema 45 or any managed runtime object. Activation or
rollback still requires separate authorization; managed tmux sessions and
Codex processes remain untouched.

## Release boundary

This candidate remains subject to bounded nonserial and serial qualification,
documentation/static/diff checks, independent review, immutable artifact
review, and separate authorization for activation, tag, push, TestPyPI/PyPI
publication, or GitHub/Gitea release. Stable v2.5.0 promotion remains held.

After a separately authorized TestPyPI publication, install the candidate with:

```bash
python -m pip install --index-url https://test.pypi.org/simple/ \
  --extra-index-url https://pypi.org/simple/ \
  agent-pbx==2.5.0rc3
```
