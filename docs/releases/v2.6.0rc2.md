# Agent PBX 2.6.0rc2

Agent PBX 2.6.0rc2 is the policy-hardening candidate for the Codex 6.2 model
integration introduced in RC1. It preserves the public and trusted-workstation
model matrices, native Codex `/model` workflow, entity-local adoption model,
and schema-46 data contract while closing two independent-review findings.

## Provider and catalog provenance

A model name alone is no longer sufficient evidence that a live selection is
one of Agent PBX's managed qualified profiles. Classification now applies this
order:

1. a non-OpenAI/ChatGPT provider is `custom_provider_observed`;
2. an empty or unavailable current catalog is `catalog_stale`;
3. a model or effort absent from the current live catalog is `unknown`;
4. an exact managed profile with trusted provider and live catalog support is
   `managed_qualified`; and
5. another supported live-catalog choice is `catalog_observed`.

Only `managed_qualified` and non-elevated `catalog_observed` choices can be
adopted into entity-local resume metadata. Custom-provider, stale-catalog, and
unknown choices remain visible as runtime evidence but fail closed at the
adoption boundary. An elevation lease does not override missing provider or
catalog provenance.

Agent PBX also re-runs classification when the operator invokes
`/codex model adopt`. A selection that was qualified when first observed is
therefore rejected if the current catalog can no longer prove it at adoption
time.

## Compatibility elevation aliases

Retained Sol 5.6 elevation names such as `sol-max`, `sol5.6-max`, and
`gpt-5.6-sol-max` now canonicalize to `sol-5.6-max` before a new lease is
persisted. Existing leases that contain one of those historical names are
canonicalized while matching an observed runtime profile.

This corrects compatibility resume and rollback behavior without making a
migration-only profile available for new role defaults or ordinary launches.

## Unchanged model policy

The committed role matrix remains:

| Surface | Committed profile |
| --- | --- |
| Caller Agent | `sol-6.2-medium` |
| Root Operator | `sol-6.2-high` |
| Edit fork | `sol-6.2-high` |
| Review fork | `sol-6.2-high` |
| Efficient task | `luna-6-high` |
| Visual task | `terra-6.1-high` |

Sol 6.2 max/ultra and Astra 6.2 xhigh/max/ultra remain bounded elevations.
Owner-local trusted-workstation overrides remain outside Git. Stars remain
lifecycle and retention state and never select a model.

The native Codex `/model` picker remains available for every choice the active
account and live catalog expose. Agent PBX observes and classifies choices; it
does not narrow the native picker or silently rewrite shared defaults.

## Upgrade and rollback

RC2 does not change the database schema. Upgrading from RC1 requires only the
package/daemon/TUI identity transition at a reviewed activation boundary; the
managed tmux server and healthy Codex processes should remain running.

Rollback restores the prior package and owner-local policy, then restarts the
daemon and TUI. No runtime mapping, Codex thread, WorkerBee lease, campaign,
approval, or project state needs to be migrated for this candidate.

## Qualification boundary

RC2 must pass:

1. focused model profile, policy, runtime, API, persistence, and TUI tests;
2. the complete parallel-safe and isolated serial pytest lanes;
3. component, OpenAPI, route, Store, schema, documentation, compilation, and
   whitespace guards;
4. isolated wheel and source-distribution builds, strict Twine validation,
   archive validation, and clean-wheel installation; and
5. a tracked acceptance receipt tied to the exact qualified source commit.

This work stops at the qualified RC2 review boundary. It does not activate the
candidate on the local daemon/TUI, change any live Codex model, push a tag,
publish a package, or promote stable v2.6.0 without separate operator approval.

  --extra-index-url https://pypi.org/simple/ \
