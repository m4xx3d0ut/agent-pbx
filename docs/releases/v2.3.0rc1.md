# Agent PBX 2.3.0rc1

Agent PBX 2.3.0rc1 is the TestPyPI qualification candidate for the v2.3
runtime-policy and resilience release. It extends the v2 control plane with
generation-bound WorkerBee runtimes, governed workspace mobility and snapshot
content, safer model elevation, more reliable managed Joplin operation,
long-running TUI resource controls, and a hardened public browser demo.

This candidate is intended for release-pipeline and activation qualification.
Production users should continue to use Agent PBX 2.2.0 until the same reviewed
changes are published as 2.3.0.

## WorkerBee runtime and workspace governance

Agent PBX now binds each Agent, Operator, edit fork, and review fork to one
verified WorkerBee backend generation and one exact workspace receipt.
Appliance-backed sessions use an Agent PBX policy gateway instead of inheriting
host OSS paths, and a generation change fails closed until the affected session
is rebound.

The control plane keeps OSS, platform-debug, and future user-appliance workspace
domains separate. New policy layers independently govern:

- tool authority, from conservative observation through bounded local deploy;
- workspace mobility through pinned, same-repository, or scoped-workbench
  movement;
- snapshot content through tracked, approved-paths, or safe-working-tree modes;
- backend selection, including loopback versus qualified native-LAN posture;
- administrator ceilings that ordinary clients cannot weaken.

The committed public default remains conservative and approval-gated. Setup
presets make standard OSS, personal appliance, trusted platform workbench, and
high-assurance workflows explicit without silently switching backends or
granting deploy authority. Review forks remain read-only under every preset.

Platform-debug materialization is content-addressed. Repeating an approved
session start can refresh changed source while retaining the Codex thread,
gateway lease, token, and backend generation; any further drift blocks mutation
until another qualified refresh. Dirty submodule content requires a host-owned,
Agent-and-source-bound include policy and contributes to binding identity.

## Runtime and operator reliability

- The F8 alert queue now keeps Operator handoff approval centers single-flight:
  repeated presses cannot stack duplicate modals, a reviewed approval can yield
  to the next report alert, and the unresolved durable record remains
  reopenable. Source Operators can withdraw exact pre-delivery handoff IDs from
  the approval center with a required reason and audited metadata/event
  evidence. Superseded requests require valid replacement IDs, while delivered,
  acknowledged, and running work fails closed.
- `Trust & approve` now rejects legacy or unstructured handoffs before opening
  its confirmation, preflights every selected handoff, suppresses duplicate
  submission, and rejects or revokes an incomplete lease after activation
  failure. A successful bounded lease still approves and dispatches the
  selected handoff, while future matching handoffs can reuse the lease.
- F9 now expands the active right-side tab workspace rather than switching to
  and maximizing only Editor. The active tab and its native Codex or editor
  surface survive collapse and restoration of the left navigation pane.
- Review-fork project-spawn requests now fail closed before approval when the
  sibling target is non-empty, the clone source is not a canonical Git root,
  or `metadata.repo_root` conflicts with the recorded review source. The TUI
  rechecks the same contract immediately before launch. Existing repositories
  remain on the qualified managed-workspace launch path rather than being
  copied, initialized, or implicitly adopted by project spawn.
- Pending project-spawn requests have authenticated inspect and idempotent
  cancel endpoints plus `/operator project spawn inspect` and
  `/operator project spawn cancel` palette actions. State transitions reject a
  canceled request being launched by a later retry.
- Managed caller launch delivers a deterministic registration bootstrap as the
  initial Codex prompt, records its digest and source Codex-session provenance,
  suppresses the startup update interstitial, and grants automatic approval
  only to the narrow Agent PBX registration/report tool allowlist. An identical
  launch retry returns the ready runtime instead of creating another pane.
- TUI-created root Operator, edit-fork, review-fork, and project-spawn panes
  register their exact configured tmux server/socket/session/window/pane
  mapping at creation time. Integrated outer-tmux mappings also retain the
  invoking session/client provenance used for targeted pop operations.
- A canceled, inactive edit fork no longer remains broker-ineligible solely
  because the TUI cached a freshly probed `missing` runtime record. Cleanup is
  target-local and requires exact Agent-to-mapping server mode/ID, socket,
  session, pane, and Codex-session provenance, no writer lease, no local
  terminal transition, a fresh local/outer listing with no target-owned pane,
  and conclusive recorded-process absence. A bare pane-ID
  collision on another tmux server is ignored only under that complete proof;
  unreadable process state and every active or ambiguous condition fail closed.
- Trusted edit forks in qualified linked Git worktrees use one of two explicit
  strategies. A direct-compatible base profile receives a launch-local Codex
  permission profile limited to that worktree's admin directory, shared object
  store, and collision-free active branch ref/reflog namespace. A split
  secret/read/deny profile receives no runtime Git-admin grant; after the fork
  is stopped, the local TUI can commit an exact root-approved leaf subset
  through `/operator git commit` and recover one exact interrupted transaction
  through `/operator git recover`. Common Git config, hooks, sibling worktree
  administration, unrelated refs, and review forks remain protected in both
  modes.
- Long broker receipts now scroll inside their own bounded review region. The
  transaction-bound confirmation input and action row stay visible, the input
  receives initial focus, and Agent PBX priority shortcuts yield only while
  that exact input owns focus. Empty or incorrect text still fails before the
  broker worker is called; the transaction, authority, receipt, and stopped-
  fork revalidation remain unchanged.
- Managed Agent launch pins Agent identity, project, cwd, PBX mode, model,
  reasoning effort, reasoning summary, verbosity, tmux binary, and runtime
  socket instead of inheriting daemon-launcher values.
- Operator campaign delivery recognizes Codex beneath a validated managed-tmux
  shell wrapper and records whether identity came from the foreground command
  or the bounded process tree.
- Prompt delivery exits tmux copy mode before submission so the input reaches
  Codex.
- Bounded Sol-max elevation is idempotent across the TUI, palette, API retries,
  and concurrent clients. One-task leases remain `revert_pending` until a
  structured safe turn boundary permits verified restart/resume on the prior
  profile.
- Agent PBX identity and bearer-token environment survive restart/resume in an
  existing managed pane.

## Long-running TUI and daemon behavior

The embedded terminal now defaults to a 10 FPS paint ceiling while continuing
to consume every PTY byte. It retains only a small renderer-side history when
tmux owns scrollback, skips redundant capture polling for an attached client,
and exposes event-loop lag, process RSS, PTY throughput, paint rate, and frame
coalescing in `Latest`.

Agent refresh and remote view persistence coalesce repeated work without
canceling in-flight HTTP requests. The TUI uses a bounded keepalive pool and
reduces HTTP polling while the event stream is healthy. Managed daemon logs
rotate during runtime with bounded size and backup counts while preserving the
daemon's open output descriptor.

The active workstation TUI has exercised this runtime baseline for more than
five continuous days, and the daemon has exercised the long-run resource paths
for more than nine days. The exact candidate still receives the standard
post-activation smoke check before stable publication.

## Managed Joplin consistency

- Daemon startup restores the configured Data API listener in `managed_cli`
  mode only after validating the profile owner, PID, executable, command, and
  socket posture.
- Profile sync waits for the listener socket itself to release, closing the
  `EADDRINUSE` race that could follow a clean process exit.
- Status reads durable queued/running state before probing a deliberately
  stopped listener, and the TUI retains known configuration and cached notes
  through a bounded restart.
- Completed `jc` writes render locally without waiting for the next refresh.
- Targeted write jobs remain Agent-scoped and cannot coalesce across owners.
- `/joplin retry write` requeues the selected Agent or Operator's latest failed
  targeted write without duplicating the note or requiring a whole-profile
  E2EE validation pass.

## Public browser demo and release media

The optional public demo now gives its root Operator and both Operator forks
independent native tmux runtimes while retaining Release Review in report mode.
Every visitor still receives isolated state, fixtures, credentials, tmux, and
processes. Demo-daemon startup chooses a fresh loopback port immediately before
spawn, distinguishes an early child exit from a readiness timeout, records only
a bounded token-redacted diagnostic tail, and retries once after a transient
failure.

The browser waits for authoritative font, iframe, visual-viewport, and Textual
Serve geometry before opening the TUI, then performs a bounded first-frame
resynchronization. An accessible Agent PBX loading surface reports startup
progress, honors reduced-motion preferences, and offers a safe retry when a
disposable session closes early.

An isolated media harness can capture deterministic ultrawide native Latest,
Operator campaign, WorkerBee, and managed Neovim scenes. It verifies frame
markers, forbidden text, geometry, source revision, and asset hashes without
attaching to workstation runtimes. Its process-liveness qualification is
portable across Linux and macOS and does not assume a Linux procfs mount.

## Compatibility and migration

Agent PBX 2.3 adds three schema-31/32 tables for WorkerBee workspace policy,
snapshot policy, and workspace transition records. The migration is additive;
existing Agent, Operator, fork, campaign, Codex-session, Joplin, editor, and
managed tmux records remain valid.

An isolated schema-30 fixture proves dry-run, apply to schema 32, retained
starred Agent/root Operator/event data, verification, and rollback to schema
30. The production upgrade still requires the normal database/configuration
backup and a reviewed activation window. Running Codex panes do not need to be
restarted solely for the package update.

The launch repair does not retroactively rewrite runtime mappings or cancel
pending requests. After activation, inspect and cancel stale pending requests
explicitly, and use the existing reconciliation preview for callers launched
before exact mapping registration. Existing healthy Codex sessions can be
retained; only callers that never received a usable session registration need
an in-place restart/resume under the repaired launcher.

An already blocked linked edit fork also keeps its current process and working
tree until a reviewed activation. Install the reviewed Agent PBX package and
restart or reopen only the TUI so it loads the new code; this source-only
TUI/validator change does not require a daemon restart. Preserve and verify the
fork's Codex session, cwd, branch, and diff. For a direct-compatible profile,
invoke guarded in-place restart/resume for only that edit fork; qualification
occurs before pane replacement, and failure leaves the pane and tree untouched.
For a broker-required split profile, stop the exact fork through the guarded
TUI lifecycle path and use the local commit review instead—do not restart it to
gain Git access. Do not relaunch a caller or restart another pane. If branch
qualification fails, stop: any branch migration is a separately approved
repository mutation, never part of this repair activation. Rollback reopens the
TUI from the previous Agent PBX package; it does not reset, clean, stash,
delete, or rewrite project content.

The post-candidate safety repair further requires complete managed tmux
provenance for every existing-pane lifecycle action. Stop, purge, restart, and
resume verify the recorded executable, socket, server, session, window, and
pane and never fall back to the default tmux server when pane IDs collide.

Linked Git-admin paths are emitted only as permission-profile filesystem
writes, never workspace or `--add-dir` roots. A Codex 0.166 provider-free
canary proved that a simple `:workspace` profile can stage and commit. It also
proved that the legacy
`sandbox_workspace_write.writable_roots` alternative cannot both preserve the
trusted profile and grant `index.lock`. Bootstrap mount-target presence is
recorded diagnostically but is not an acceptance signal because Codex
materialization/cleanup timing can vary between otherwise identical runs; the
authorization boundaries remain deterministically unsafe.

For the incompatible split profile, the new TUI-local broker preserves all
denials rather than restarting Codex with broader access. It requires a
canonical stopped edit fork on a dedicated `pbx-operator-N/...` branch, an
initially empty staged set, explicit enumerated leaves, a recomputed four-path
topology, and a typed transaction confirmation. Receipt review displays raw
SHA/blob and prior-index identities for each leaf plus branch, HEAD/tree,
index, upstream, ref, reflog, transaction, and authority identities. Raw bytes
are committed without attributes or filters, so unrelated protected dirt is
never enumerated or opened. Include/includeIf, partial clone/promisor, object
alternates, replacement objects, lazy fetch, hooks, caller environment, sparse
or split indexes, and unmerged state all fail closed.

Git-index extension detection now parses the declared `DIRC` v2-v4 entry table,
object-ID width, padding, extension boundaries, and SHA-1/SHA-256 checksum. This
removes a false positive where ordinary tracked path bytes containing `link`
were mistaken for the split-index extension. Actual `link`/`sdir` extensions,
unknown mandatory extensions, unsupported formats, malformed path compression,
truncation, overflow, and impossible boundaries remain fail-closed errors.

The broker creates approved blobs/tree/commit in a private object quarantine,
durably journals their exact manifest, and only then installs that bounded set.
Index/ref/reflog updates use locks and compare-and-swap with exact recovery.
Standard Git object creation is append-only: after a later race or rollback,
the journaled approved-content objects may remain unreachable for normal Git
garbage collection. Shared objects are never deleted during rollback.

Activation remains per fork. Operator-7's preserved stopped legacy record may
be accepted only when fresh qualification proves the exact same topology and
four paths; its current branch and approved leaf subset still require a
separately authorized read-only review before any commit. Operator-8 remains
ineligible while active/blocked. It requires a separately authorized guarded
stop, and its protected pre-existing paths and dirt must remain outside broker
candidate input and observation. Neither contract authorizes a runtime restart,
implicit staging, branch migration, or commit by package installation alone.

Compatibility polling, Thread, HTTP refresh, and captured-terminal paths remain
available. The managed PaaS/user-appliance materializer remains unavailable
until its volume and lifecycle boundary is qualified.

## TestPyPI qualification

The release candidate is accepted only after:

- documentation, wiki, compilation, and diff gates;
- the complete parallel and isolated serial pytest lanes;
- strict release metadata and immutable-tag validation;
- isolated PEP 517 wheel and source-distribution builds;
- strict Twine and archive-hygiene checks;
- clean virtual-environment installation from the exact wheel;
- the hosted Linux/macOS and Python 3.10/3.12 matrix;
- TestPyPI Trusted Publishing, public hash comparison, and clean installation.
