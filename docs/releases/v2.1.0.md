# Agent PBX 2.1.0

Agent PBX 2.1 completes the first post-v2 native-runtime hardening cycle. It
adds a reversible path for adopting existing Agents into PBX-managed tmux
runtimes, a guided managed-workspace launcher, more reliable native Codex input
and scrollback, smoother right-pane transitions, and lower refresh overhead.

The product boundary introduced in v2.0 remains unchanged: Agent PBX owns
durable Agent and Operator identity, lifecycle, policy, routing, campaigns,
approvals, runtime mappings, and audit. Codex owns reasoning and execution
inside each root session. Tmux owns durable PTYs, panes, history, attachment,
and geometry. WorkerBee remains the optional runtime-truth and infrastructure
capability plane.

## Native Agent adoption and recovery

Existing Agents can be adopted into native PBX-managed terminal runtimes with
a previewable, reversible transition. Adoption records the source and target
runtime evidence, prefers the current Codex rollout, recognizes declared
runtime aliases, and verifies the resulting session before retiring a source
mapping.

Restart and recovery paths now preserve a healthy source pane when the
replacement does not stabilize. Native runtime reconciliation is stricter
about pane identity, process evidence, tmux server selection, origin clients,
and resize targets so stale identifiers cannot silently target an unrelated
process.

## Embedded Codex terminal

The `Latest` tab continues to host a PTY-backed normal tmux client. Version
2.1 hardens the full interaction path:

- printable keys reach Codex while the embedded terminal owns focus;
- `Ctrl+C` and `Ctrl+P` reach the child terminal under terminal focus;
- plain configured function keys remain global PBX navigation;
- modified function keys continue to translate to child function keys;
- `F3` moves focus to the right-side tab row;
- `PgUp` enters runtime tmux scrollback;
- reading-view navigation supports arrows and page keys;
- configurable newline input supports terminal clients that do not expose a
  convenient multiline chord;
- popup and selector cancellation redraw the underlying Codex frame cleanly;
- disabling native mode detaches the disposable client and releases its writer
  lease;
- targeted pop-out resolves the invoking outer tmux client from live evidence
  when older adopted metadata lacks a client TTY;
- terminal handoffs avoid briefly flashing the capture/input fallback while a
  new native surface attaches.

These paths were exercised from desktop Linux and Android/Termux over SSH.
Tmux remains the scrollback owner, with Codex configured for inline rendering.

## Managed workspace launch

Configure approved project roots with a platform path separator:

```bash
AGENT_PBX_PROJECT_ROOTS="$HOME/git:$HOME/worktrees"
```

Restart the daemon after changing the roots. Press `F10`, run
`/workspace launch`, or use `/agent launch` to select a discovered Git project
and launch a caller Agent. The launch dialog can also create its root Operator
and default edit fork. Launch is transactional: failure cleans up partial PBX
entities and runtime resources rather than leaving an orphan.

## Lifecycle and operator UX

- Agent and Operator lists retain their order while the operator is actively
  navigating them, preventing cursor and item jumps during background updates.
- Acknowledging a root Operator alert also acknowledges the corresponding
  non-review fork status that produced it.
- `F8` focuses and acknowledges one pending Agent or Operator alert at a time,
  cycling through additional alerts on subsequent presses.
- Palette and modal actions retain their intended entity target after dialogs
  close.
- Joplin response captures again include a truncated prompt summary in the
  generated note title.

## Performance and release tooling

Schema 29 adds indexes used by Agent summary refreshes. Embedded terminal
rendering coalesces unchanged frames and avoids redundant paints, improving
typing and selection latency. The test runner now supports bounded parallel
lanes while keeping host-resource tests isolated.

The public hero is generated from deterministic v2 fixtures and shows the
native terminal, managed launch, Operator workflows, and the current right-side
feature surfaces.

## Installation and upgrade

Read [the v2 installation guide](../install-v2.md) before upgrading a running
daemon.

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
agent-pbx mcp stop
agent-pbx migrate apply
agent-pbx migrate verify
agent-pbx mcp start
```

Restart connected TUI clients after the daemon. Existing Codex Agents and
Operators do not need to be restarted solely for the Agent PBX package update.
Verify representative retained mappings and native attachments, then retain
the backup for at least seven days.

The schema 28 to 29 change is additive and index-only. Rollback still uses the
verified pre-upgrade database and configuration backup; it does not delete
newer project files, Codex transcripts, Joplin notes, or project trash.

## Compatibility

Polling/nohup mode, Thread, HTTP refresh, and terminal capture remain supported
in Agent PBX 2.1.0. Native tmux and sequenced WebSocket events are preferred for
local clients. Legacy-path removal still requires measured parity, a supported
migration path, and published notice.

See [the v2.1 acceptance record](../acceptance/v2.1-uat.md) for the automated,
host-migration, native-terminal, packaging, and release evidence.
