# Agent PBX 2.2.0

Agent PBX 2.2.0 closes the first post-v2.1 operator-UX cycle. It adds isolated
integration qualification, managed terminal editors, transactional WorkerBee
backend selection for future sessions, a guarded Git wiki release workflow,
and the previously qualified setup, history, child-activity, responsive-layout,
and Joplin clipboard work.

The release preserves the Agent PBX v2 control-plane boundary. Agent PBX owns
durable identity, lifecycle, policy, routing, and runtime mappings; Codex owns
reasoning and execution within each session; tmux owns terminal persistence;
and WorkerBee remains an optional runtime-truth plane.

## Isolated integration harness

- Harness runs receive private HOME, XDG, state, database, port, token, tmux,
  and fixture-integration resources.
- Atomic private manifests record source revision, process identity, commands,
  and cleanup state.
- Guarded cleanup acts only on the run's owned resources.
- WorkerBee binding receipts record source and workspace digests and reject
  drift. A local snapshot remains explicitly unbound until the selected
  endpoint proves an allowed import path.

This path lets maintainers qualify integration changes without restarting or
rewiring production Agents and Operators.

## Managed terminal editors

The Editor tab can start a fileless project workspace in Neovim, Vim, Nano, or
an operator-configured allowlisted profile. Profiles contain structured
`argv`/`workspace_argv` arrays rather than shell command text. Users can select
Textual or terminal as their default editor surface, and Files exposes explicit
default, Textual, and native open actions.

Each editor gets a dedicated editor-only tmux server. It does not share the
Codex runtime socket, pane, process, mapping, or writer lease. Closing the
embedded client leaves the editor process available; the explicit stop action
terminates only that editor runtime and reloads the file through the normal
conflict-aware path.

Managed editor identity is durable across TUI and daemon restarts. Agent PBX
adopts a saved editor only after validating its private socket, exact pane,
PID/start-time evidence, project root, and, for Neovim, private RPC socket.
Opening approved files from Files reuses a running Neovim workspace with
tab-drop behavior, preserving existing buffers and tabs while reusing a file
already displayed. File routing preserves the requested line and applies the
same project-root, sensitive-path, traversal, symlink, and regular-file checks
used by the Textual editor. Switching back to a clean Textual buffer refetches
the file to reflect native-editor writes.
Stale records fail closed and have an explicit forget action that cannot stop a
live process. The combined runtime-bundle endpoint reports Codex and editor
readiness without merging their ownership or process lifecycles.

## Transactional WorkerBee backend selection

When the host configures compatible status and switch helpers, an operator can
preview OSS or platform-debug selection from the WorkerBee tab or command
palette. The transaction binds apply to:

- the exact non-mutating dry-run plan and target;
- the current backend fingerprint;
- a private, expiring preview token;
- exact typed confirmation, plus privileged confirmation for platform-debug;
- post-apply backend provenance and WorkerBee MCP capability verification.

A failed verification attempts to restore the prior backend and records the
result. The last verified switch also supports explicit rollback. Backend
selection applies to future sessions; Agent PBX does not rewrite the MCP
binding of a running Codex session.

## Guarded project wiki publication

The repository-owned wiki source can now be checked and staged locally:

```bash
agent-pbx wiki check --source docs/wiki
agent-pbx wiki stage --source docs/wiki --output artifacts/wiki-stage \
  --revision "$(git rev-parse HEAD)"
```

Staging rewrites wiki navigation links, pins repository links to the selected
revision, generates the sidebar, records per-page SHA-256 checksums, and emits
a deterministic archive. Publication is a separate operation that requires
the exact reviewed stage digest and an explicit `.wiki.git` remote. It updates
only managed page names, preserves unknown remote pages, and follows the
remote wiki's advertised default branch unless explicitly overridden.

## Completed 2.2 work

- The setup assistant retains preview/apply/resume/rollback and scoped private
  configuration behavior.
- F11/F12 navigate per-client Agent, Operator, and right-tab history while
  safely skipping stale or hidden destinations.
- Command palette history is bounded, deduplicated, excludes prompt bodies and
  sensitive command classes, and persists only by explicit opt-in.
- Qualified Codex child activity appears as a bounded structured projection
  below its owning PBX entity without creating a peer identity or exposing
  prompts, paths, hidden reasoning, or inferred roles.
- Adaptive, split, compact, and tiny layouts retain focus and terminal access.
- Joplin reading/editing supports explicit guarded clipboard copy and paste,
  stable note selection, and revision-scoped reading positions.
- WorkerBee diagnostics distinguish capability-policy, endpoint, version,
  backend-provenance, and path-visibility failures.

## Compatibility and migration

Agent PBX 2.2.0 adds an additive schema migration for durable managed-editor
runtime identities. Existing Agent, Operator, fork, campaign, Codex-session,
Joplin, and managed tmux mappings remain valid. Run the documented migration
backup, apply, and verify sequence before starting the updated daemon.
Compatibility polling, Thread, HTTP refresh, and captured-terminal paths remain
available.

Install the package, restart the Agent PBX daemon, and restart connected TUI
clients to load the new code. Running Codex sessions do not need to restart
solely for this Agent PBX update. Configure terminal editor and WorkerBee
switcher helpers only when those optional controls are wanted.

```bash
python -m pip install --upgrade agent-pbx==2.2.0
```

Before upgrading a long-lived control plane, run doctor and retain a current
database/configuration/runtime-mapping backup. Keep rollback artifacts until
the reviewed retention period ends, then preview and explicitly confirm any
prune action.
