# Agent PBX 2.1.1

Agent PBX 2.1.1 is the first maintenance release for the v2.1 control plane.
It hardens managed Codex runtime recovery across mixed tmux versions, restores
the intended terminal color and syntax-theme behavior, repairs Joplin E2EE
sync and reading-state handling, and introduces a fully qualified secretless
release pipeline for PyPI.

The release preserves the Agent PBX 2.1 architecture and schema. Existing
Agent, Operator, Codex-session, campaign, Joplin, and managed tmux mappings do
not require a data migration.

## Managed Codex runtime recovery

- Explicit restart creates a fresh v2 managed tmux mapping when an Agent or
  Operator has no usable mapping, resumes the preserved Codex session, and
  verifies the replacement before recording it.
- Runtime commands use each mapping's exact tmux executable, socket, session,
  window, and pane. This prevents the host tmux 3.2 server from being confused
  with PBX-managed tmux 3.7 sessions.
- Operator follow-up delivery, scrollback, rollout lookup, resize, copy mode,
  and shutdown all follow the recorded runtime identity.
- Codex shutdown uses the supported `/quit` command and recognizes a stopped
  Codex process even when the tmux pane returns to its shell.

## Terminal color and syntax themes

- Agent PBX installs and selects the generated `agent-pbx-1337` Codex syntax
  theme through a drift-safe command and reports its state through doctor.
- Dedicated tmux runtime reconciliation removes stale inherited `NO_COLOR`
  state while preserving an explicit user request to suppress color.
- The original `cyberpunk` RGB palette is restored. The
  `cyberpunk-accessible` theme remains a distinct deuteranopia-friendly
  deep-teal alternative, including under an outer tmux 3.2 workspace.

## Joplin E2EE and response capture

- Same-profile Data API and CLI sync operations are serialized under an
  explicit profile-ownership policy.
- Encrypted notes render as locked rather than empty, and Agent PBX blocks
  mutation until decryption succeeds.
- Managed sync restores the exact validated Joplin Data API process without
  exposing E2EE credentials or ciphertext.
- Targeted response writes validate note identity and retain Codex session,
  transcript, turn-phase, line, mtime, and response-hash provenance.
- The TUI preserves note selection, reading state, and dirty drafts while the
  managed sync path restarts and verifies the Data API.

## Trusted Publishing

Agent PBX now publishes its wheel and source distribution through separate
TestPyPI and production PyPI Trusted Publishers:

- release identity validation binds package version, annotated tag, commit,
  changelog, release document, and target-index state;
- Linux and macOS test lanes qualify Python 3.10 and 3.12;
- an isolated job builds the public wheel and source distribution once;
- the publish job receives a short-lived OpenID Connect credential only after
  the protected GitHub environment is approved;
- PyPI receives PEP 740 publish attestations for both distributions;
- post-publish verification compares public hashes to the exact tested
  artifacts and performs a clean installation from the package index.

No PyPI API token or publishing password is stored in GitHub. The production
package files remain separate from the checksummed Linux wheelhouse and
installer attached to the GitHub Release.

The `2.1.1rc1` rehearsal passed the complete TestPyPI path before this stable
release was prepared, including OIDC publication, public Integrity API
provenance, hash comparison, and clean installation.

## Upgrade

Install from PyPI after publication:

```bash
python -m pip install --upgrade agent-pbx==2.1.1
```

For an existing local control plane, back up configuration and state, install
the package, restart the daemon, and restart connected TUI clients. Running
Codex sessions do not need to be restarted solely for this package update.

See [the release procedure](../releasing.md),
[the v2 installation guide](../install-v2.md), and
[the v2.1 acceptance record](../acceptance/v2.1-uat.md) for operational and
validation detail.
