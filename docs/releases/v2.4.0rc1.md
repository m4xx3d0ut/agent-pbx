# Agent PBX 2.4.0rc1

Agent PBX 2.4.0rc1 is the first release candidate for the durable engineering
control-plane cycle. It extends the v2.3 Agent, Operator, campaign, handoff,
authority, managed-tmux, WorkerBee, and audit foundations with reusable
engineering evidence and resource primitives while retaining conservative
public defaults.

This is a prerelease. Production users should remain on Agent PBX 2.3.0 until
the exact RC artifacts pass GitHub and TestPyPI qualification, reviewed
workstation activation, rollback verification, and representative
Agent/Operator/Joplin/native-terminal UAT.

## Release boundary

The candidate advances the additive database contract from schema 40 to schema
45 and includes 19 focused commits after v2.3.0. The cumulative boundary is:

| Surface | 2.4.0rc1 capability | Default posture |
| --- | --- | --- |
| Exact Git review | Receipt-bound, bounded text/binary review artifacts for exact approved leaves, including multi-parent identity | Available only through qualified broker/review flows |
| Evidence export | Daemon-owned JSON, Markdown, and NDJSON exports for threads, campaigns, and filtered evidence cases | Disabled unless a private export root and feature gate are configured |
| Operator KB bundle v2 | Deterministic revisions, reconciliation, conflict/tombstone handling, reviewer evidence, and private-Git preparation | Disabled; publication and active import remain root-Operator actions |
| Durable helpers | Content-addressed helper bundles with exact-path proposal, isolated validation, lifecycle review, read-only materialization, import/export, and reuse metrics | Disabled; helper roots and proposal roots must be explicit |
| Dynamic resources | Typed requests, approval, bounded leases, provider receipts, recovery, release, and zero-residue cleanup | Disabled; public policy is manual and high-risk classes remain unavailable |
| WorkerBee development resources | Capability-gated managed venv, cache, scratch, generated-output, service-state, and Unix-runtime overlays | Disabled; requires a separately qualified private adapter |
| Protected-provider preflight | Metadata-only Git/workspace/provider-generation reconciliation | Always manual; no provider execution, credentials, merge, publication, or deployment |
| Operator workflow projection | Event-driven `State`, `Flow`, `Camp`, and `Live` semantics with reason/source/subject detail | Enabled as a compatibility repair |

## Durable engineering evidence

Exact Git review artifacts bind the approved path set, parent and tree
identity, modes, bounded raw content, rendered diffs, truncation metadata, and
artifact digest. Revalidation rejects path, scope, content, parent, or digest
drift before broker execution. Unrelated working-tree content remains outside
the review artifact.

The evidence export center uses positive field selection rather than serializing
internal records. Hidden reasoning, prompt bodies, terminal history, event
payloads, credentials, provider receipts, and secret probes remain excluded by
default. Every export is written under an owner-private daemon root with a
content manifest and verification digest. Retention remains preview-only until
a separately authorized prune action exists.

## Knowledge and durable helpers

KB bundle v2 provides deterministic import/export preparation, stable entry
revisions, linear reconciliation, explicit conflicts, tombstones, and reviewer
evidence. It does not carry ambient Git credentials or publish itself. Review
forks may continue to search active knowledge and propose entries, but only a
root Operator may publish, update, reject, retire, import, or export active
knowledge.

Durable helpers are deliberately separate from KB prose. A helper is proposed
from one exact allowed path, validated in isolation without executing its
payload, reviewed through a closed lifecycle, and materialized read-only by
content digest. Export/import is digest-bound and idempotent. Optional
content-free measurements expose reuse and churn without storing command
arguments or helper output.

## Typed development resources

The dynamic-resource broker replaces ad hoc temporary infrastructure requests
with a closed contract bound to Operator authority, campaign or handoff,
workspace digest, TTL, quota, approval identity, lease, provider receipt, and
cleanup evidence. There is no generic command, executable, environment,
arbitrary host path, device, or credential surface.

Low-risk local classes can be admitted by reviewed policy. Network endpoints,
host sockets, devices, credentials, provider/cloud changes, publication,
deployment, and destructive actions remain denied by the automatic path. Team
work requires a bounded delegation lease. A trusted single-user profile may
auto-approve only its reviewed workspace-local low-risk subset.

WorkerBee development resources add a closed adapter contract for managed
virtual environments, caches, build/test scratch, generated-output staging,
service state, and Unix runtime sockets. Every request binds the exact
workspace binding, backend generation, capability digest, fixed mount target,
owner/mode, quota, and expiry. Trusted-direct source remains read-only and
`rprivate`; overlay authority never implies source-write or controlled-run
authority.

The open-source package contains the contract, validation, orchestration, and
fixture. It does not contain or enable the private platform-debug adapter.
Activation requires that adapter to pass the checked-in byte-compatible
capability/acquire/status/release fixture and isolated zero-residue UAT.

## Operator workflow state

The Operators pane now has explicit semantics:

- `State` is Agent PBX's highest-priority durable workflow projection;
- `Flow` is the projected route or action;
- `Camp` is the number of active nonterminal campaigns; and
- `Live` is tmux/runtime liveness.

Raw Codex terminal activity does not drive `State`, `Flow`, or `Camp`.
Approvals, controlled runs, handoff receipts, guarded actions, and campaigns
retain priority over heartbeat staleness. When no higher-priority durable work
exists, a stale heartbeat is no longer hidden by an old `working` or `waiting`
report. Selecting an Operator shows the projection reason, source, and durable
subject identity in Latest.

Workflow-changing report, campaign, handoff, broker, delegation-lease,
dynamic-resource, and WorkerBee controlled-run events now trigger the existing
bounded and coalesced Agent refresh path. The change adds no unbounded polling
or independent refresh worker.

## Compatibility and security posture

The new engineering subsystems are additive and default-disabled. Existing
public behavior remains unchanged until each gate is explicitly enabled.
Review forks remain non-mutating. Backend, source mode, access profile,
execution lane, resource authority, and provider authority remain independent.

The protected-provider diagnostic is not provider authority. It recomputes and
binds metadata-only Git and workspace evidence, opaque provider generations,
approval identity, and expiry. It has no credential reader, provider adapter,
merge/write command, runtime lifecycle operation, publication path, or deploy
path.

Primary gates introduced or qualified in this cycle include:

```text
AGENT_PBX_EVIDENCE_EXPORTS_ENABLED
AGENT_PBX_EVIDENCE_EXPORT_ROOT
AGENT_PBX_OPERATOR_KB_BUNDLE_V2_ENABLED
AGENT_PBX_DURABLE_HELPERS_ENABLED
AGENT_PBX_DURABLE_HELPER_ROOT
AGENT_PBX_DURABLE_HELPER_PROPOSAL_ROOTS
AGENT_PBX_DURABLE_HELPER_MEASUREMENTS_ENABLED
AGENT_PBX_DYNAMIC_RESOURCES_ENABLED
AGENT_PBX_WORKERBEE_DEVELOPMENT_RESOURCES_ENABLED
```

See the architecture decisions under `docs/adr`, the Operator authority wiki,
and the [v2.4 acceptance record](../acceptance/v2.4-uat.md) before enabling any
of these controls.

## Migration and rollback

Before activation:

1. record the exact RC commit and package hashes;
2. back up the Agent PBX database, configuration, runtime mappings, and current
   installed package identity;
3. run migration dry-run against a copied database;
4. verify schema 45 and SQLite integrity after apply;
5. restart only the Agent PBX daemon, preserving the managed tmux server and
   Codex processes;
6. launch the TUI through the reviewed local wrapper and verify retained
   Agents, Operators, forks, stars, campaigns, sessions, panes, Joplin,
   WorkerBee, model policy, and editor state.

Rollback is feature-local first: disable the affected gate, deny new work,
release only exact receipt-bound resources, and retain immutable evidence for
review. Restore the pre-activation database/configuration/package only after
leased resources are terminal. Ambiguous provider state remains
`recovery_required`; rollback must never infer a path or delete shared state.

After TestPyPI publication:

```bash
python -m pip install \
  --index-url https://test.pypi.org/simple \
  --extra-index-url https://pypi.org/simple \
  agent-pbx==2.4.0rc1
agent-pbx --version
```

## Promotion criteria

Stable 2.4.0 should be derived from this candidate by release identity and
documentation only after:

1. exact-tag GitHub quality and artifact jobs pass;
2. TestPyPI hashes and clean installation match the tested artifacts;
3. schema backup, migration, integrity, and rollback evidence are reviewed;
4. local managed activation preserves all retained entities and runtimes;
5. representative native terminal, Operator workflow, Joplin, WorkerBee,
   evidence, knowledge, and helper paths pass UAT; and
6. no semantic repair is required.

Any semantic runtime change requires another release candidate.
