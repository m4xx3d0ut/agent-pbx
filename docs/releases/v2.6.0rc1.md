# Agent PBX 2.6.0rc1

Agent PBX 2.6.0rc1 is the first release candidate for the Codex 6.2 model
policy cycle. It preserves the v2.5 runtime, WorkerBee, campaign, terminal,
and authority contracts while adding versioned Sol, Astra, Luna, and Terra
profiles plus direct integration with Codex's native `/model` picker.

This candidate does not advance the database schema. Schema 46 remains current,
so a qualified v2.5 database needs no data migration.

## Model policy matrix

| Surface | Committed profile | Policy |
| --- | --- | --- |
| Caller Agent | `sol-6.2-medium` | Portable everyday default |
| Root Operator | `sol-6.2-high` | Cross-project coordination default |
| Edit fork | `sol-6.2-high` | Root-supervised implementation default |
| Review fork | `sol-6.2-high` | Read-only review default |
| Efficient task | `luna-6-high` | Focused, repeatable, high-volume work |
| Visual task | `terra-6.1-high` | Visual understanding and computer use |
| Sol elevation | `sol-6.2-max`, `sol-6.2-ultra` | Bounded human-approved lease |
| Astra elevation | `astra-6.2-xhigh`, `astra-6.2-max`, `astra-6.2-ultra` | Bounded human-approved lease |

The public control mode is `guard_elevated`. Current live-catalog choices are
observable and usable while max and ultra remain behind the existing approval
and lease workflow. Ultra profiles also require observed subagent capability.

An owner-only `model-policy.toml` can raise or specialize role defaults without
changing repository defaults. Invalid local values fall back with diagnostics,
and group- or world-readable policy files produce a permissions warning.

## Native Codex model integration

`/codex model native` opens the selected runtime's native Codex model picker.
Agent PBX observes structured thread-setting updates and reports the effective
model, effort, provider, evidence source, and policy classification in the
Codex tab.

Selections are classified as:

- `managed_qualified` for an exact versioned PBX profile;
- `catalog_observed` for a current Codex catalog choice;
- `custom_provider_observed` for a configured non-OpenAI provider;
- `catalog_stale` when current catalog evidence is unavailable; or
- `unknown` when the selection cannot be reconciled.

`/codex model adopt` stores an eligible choice only in the selected entity's
resume metadata. It never changes repository defaults, workstation role
defaults, or the global Codex configuration. `/codex model return` restarts and
resumes the entity on its current role default.

Elevated adoption requires an exact managed profile and a matching, unexpired,
approved or active lease. Arbitrary elevated catalog choices, provider-only
choices, stale observations, and unknown selections fail closed.

## Compatibility and migration

Exact Sol 5.6, Terra 5.6, and Codex 5.5 compatibility profiles remain
available for retained metadata, resume, evidence, and rollback. They are
marked migration-only and cannot launch a new entity or become a shared
default.

Existing Agents and Operators keep their explicit model metadata. Updating the
role policy does not interrupt a running Codex process or rewrite an entity.
Operators can migrate an entity at a reviewed turn boundary, adopt a direct
non-elevated catalog choice, or return it to the current role default.

Stars remain lifecycle and retention state. They have no model-selection side
effect.

## Architecture and API boundary

The additive entity-local adoption endpoint is included in the reviewed
OpenAPI and route inventories. The model profile registry, policy loader,
runtime projection, and command construction live outside the TUI composition
root. Duplicate palette-name state has been removed, and the existing
component-growth ceilings remain enforced.

No WorkerBee profile, filesystem authority, Git authority, credential scope,
provider authority, tmux mapping, writer lease, or campaign topology is changed
by this release candidate.

## Upgrade and rollback

Before loading the candidate on a long-lived workstation:

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
```

The expected schema result from v2.5 is `changes_required=false`. Load the
candidate by restarting only the Agent PBX daemon and TUI. Do not restart the
managed tmux server or healthy Codex processes for this upgrade.

Verify the daemon/package identity, schema 46, model-policy source and hash,
live Codex catalog, retained runtime mappings, and role defaults. Restart an
individual Codex session only at a reviewed turn boundary when intentionally
changing its model or refreshing its MCP inventory.

Rollback restores the v2.5 package and local policy file, then restarts the
daemon and TUI. Managed tmux sessions and healthy Codex processes remain
untouched. Exact migration profiles preserve old model metadata during the
rollback window.

## Qualification boundary

RC qualification requires:

1. focused profile, policy, runtime, event-bridge, API, TUI, demo, and UAT
   tests;
2. component, OpenAPI, route, Store, schema, documentation, and static guards;
3. the complete parallel-safe and isolated serial pytest lanes;
4. distribution and release-metadata validation;
5. an independent review of catalog, policy, elevation, and compatibility
   behavior; and
6. a managed local canary at safe turn boundaries before stable promotion.

This release task stops at the qualified RC review boundary. Stable v2.6.0
publication requires a separate final approval.
