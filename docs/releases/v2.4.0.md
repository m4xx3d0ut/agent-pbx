# Agent PBX 2.4.0

Agent PBX 2.4.0 is the stable release of the durable engineering
control-plane cycle qualified through `v2.4.0rc2`. It extends the v2.3 Agent,
Operator, campaign, handoff, authority, managed-tmux, WorkerBee, and audit
foundations with reusable engineering evidence, knowledge, helpers, and
resource controls while retaining conservative public defaults.

The stable identity is derived from the exact RC2 product tree by version and
release documentation only. RC2 passed the full Linux/macOS and Python
3.10/3.12 matrix, TestPyPI Trusted Publishing, registry-hash verification,
clean installation, and managed workstation activation before this release
was prepared.

## Durable engineering control plane

| Surface | 2.4 capability | Default posture |
| --- | --- | --- |
| Exact Git review | Receipt-bound text/binary review artifacts for exact approved leaves, including parent, tree, mode, raw-byte, and digest identity | Qualified review and broker flows only |
| Evidence export | Daemon-owned JSON, Markdown, and NDJSON for threads, campaigns, and filtered evidence cases | Disabled until a private export root and feature gate are configured |
| Operator KB bundle v2 | Deterministic revisions, reconciliation, conflicts, tombstones, reviewer evidence, and private-Git preparation | Disabled; active import/export and publication remain root-Operator actions |
| Durable helpers | Content-addressed proposals, isolated non-executing validation, lifecycle review, read-only materialization, import/export, and reuse metrics | Disabled; helper and proposal roots must be explicit |
| Dynamic resources | Typed requests, approval, bounded leases, provider receipts, recovery, release, and zero-residue cleanup | Disabled; public policy is manual and high-risk classes remain unavailable |
| WorkerBee development resources | Capability-gated managed venv, cache, scratch, generated-output, service-state, and Unix-runtime overlays | Disabled; requires a separately qualified adapter |
| Protected-provider preflight | Metadata-only Git, workspace, approval, expiry, and opaque provider-generation reconciliation | Always manual; grants no provider execution, credentials, publication, or deployment |
| Operator workflow projection | Event-driven `State`, `Flow`, `Camp`, and `Live` with reason/source/subject detail | Enabled as a compatibility and observability repair |

## Evidence, knowledge, and helpers

Exact Git review binds the approved path set, raw bytes, modes, rendered and
bounded diffs, parent and tree identity, and artifact digest. Drift in path,
scope, content, parent, tree, or digest is rejected before broker execution.
Unrelated working-tree content remains outside the review artifact.

Evidence export uses positive field selection rather than serializing internal
records. Hidden reasoning, prompt bodies, terminal history, credentials,
provider receipts, and secret probes remain excluded by default. Exports live
under an owner-private daemon root with a manifest and verification digest.

KB bundle v2 supports deterministic import/export preparation, stable entry
revisions, linear reconciliation, explicit conflicts, tombstones, and reviewer
evidence without carrying ambient Git credentials or publishing itself.
Review forks may search and propose; root Operators retain active knowledge
publication, update, rejection, retirement, import, and export authority.

Durable helpers are content-addressed executable artifacts rather than KB
prose. Agent PBX validates each exact allowed path in an isolated,
non-executing Python process, records immutable lifecycle receipts, and
materializes approved content read-only by digest. Import/export remains
digest-bound and idempotent.

## Typed development resources

The dynamic-resource broker replaces ad hoc temporary infrastructure requests
with a closed request model bound to Operator authority, campaign or handoff,
workspace digest, TTL, quota, approval identity, provider receipt, and cleanup
evidence. It exposes no generic executable, command, arbitrary environment,
host path, device, or credential surface.

WorkerBee development resources use the same bounded model for managed virtual
environments, caches, build/test scratch, generated-output staging, service
state, and Unix runtime sockets. Every request binds the exact workspace,
backend generation, capability digest, target, owner/mode, quota, and expiry.
Trusted-direct source remains read-only; writable overlay authority does not
imply controlled-run, deployment, or provider authority.

The open-source package includes the contract, orchestration, validation, and
fixture. It does not include or silently enable a private platform-debug
adapter.

## Operator workflow state

The Operators pane now separates durable workflow from process liveness:

- `State` is Agent PBX's highest-priority durable workflow projection;
- `Flow` is the projected route or action;
- `Camp` counts active nonterminal campaigns; and
- `Live` reports tmux/runtime liveness.

Raw Codex terminal activity does not rewrite durable workflow state.
Approvals, controlled runs, handoff receipts, guarded actions, and campaigns
retain precedence, while stale heartbeat state is visible when no higher
priority work remains. Selecting an Operator exposes the projection reason,
source, and subject identity.

## Compatibility and security

The database contract advances additively from schema 40 to schema 45.
Migration and rollback qualification preserves Agents, Operators, forks,
stars, campaigns, handoffs, sessions, tmux mappings, and retained
compatibility surfaces.

All high-authority engineering subsystems remain additive and
default-disabled. Review forks remain non-mutating. WorkerBee backend, source
mode, access profile, execution lane, resource authority, provider authority,
deployment, publication, and credentials remain independent controls.

The durable-helper validator accepts a shared-write Python executable only
when strict resolution proves it is the interpreter already running Agent PBX.
Every separately configured interpreter retains the no-group-or-world-write
rule. Regular-file, owner-execute, isolated compilation, private harness, and
before/after executable-identity checks remain mandatory.

## Upgrade

Before upgrading a long-lived control plane:

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
agent-pbx mcp stop
agent-pbx migrate apply --retention-days 7
agent-pbx migrate verify
agent-pbx mcp start
agent-pbx doctor
```

Do not restart the managed tmux server or healthy Codex processes solely for
this upgrade. Restart the daemon and connected TUI clients so they load the
new package, then verify runtime mappings, schema identity, Joplin, WorkerBee,
model policy, and managed editor state.
