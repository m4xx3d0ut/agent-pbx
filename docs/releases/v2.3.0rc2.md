# Agent PBX 2.3.0rc2

Agent PBX 2.3.0rc2 is the local review candidate for the WorkerBee three-mode
architecture added after rc1. It keeps backend selection, source mode, access
profile, and execution lane independent and makes their effective policy
visible through typed API and doctor readback.

## WorkerBee contracts

- Source modes are explicit: `native-direct`, `snapshot-import`,
  `trusted-direct-bind`, and `managed-clone`.
- Access profiles are explicit: `observe-local`, `review-readonly`,
  `local-deploy`, and `trusted-workbench`. Trusted Workbench may be labeled
  `Rosie Workbench` locally without changing its durable identity.
- The ordinary generation-bound gateway remains separate from the root-owned
  immutable controlled-run lane.
- The fresh public policy remains `snapshot-import` plus `local-deploy` and the
  ordinary gateway lane. Legacy receipts with omitted source metadata migrate
  to their prior backend-equivalent behavior without changing that public
  policy.
- Required capability families expand to a fixed tool registry. Reviewed
  backend-optional tools may augment that surface. Unknown advertised tools are
  quarantined, denied at invocation, exposed as non-nominal readback, and
  reported by doctor.

The reviewed source-side catalog is
`tests/fixtures/workerbee_tool_catalogs_rc2.json`. Live OSS and private
platform-debug catalogs must advertise every required tool for the selected
profile, and callable backend-only additions must match the reviewed optional
registry. Comparing those live catalogs is a separate post-review integration
gate; it is not part of this source-only checkpoint.

## Trusted direct bind

`trusted-direct-bind` is platform-debug-only, requires an administrator ceiling,
canonical approved roots, safe ownership and ancestry, and a host-owned helper
receipt. Admission occurs before source identity reads, and every source-
consuming operation revalidates the runtime and helper evidence. Release uses
the helper cleanup contract and fails closed on residue. The checked-in
2,768-byte adapter conformance fixture binds exact verify/release fields,
canonical WorkerBee receipt identity, protected-mask counts and digest,
private-group evidence, helper identity, and zero-residue cleanup. It is not
selected by public defaults; live private-helper conformance remains a
post-review activation gate.

Agent PBX treats helper-owned source, path-component, and adapter receipt
digests as opaque 64-hex linkage evidence and requires exact admitted values
during operation-time verification and release. Byte-exact admission, verify,
and release conformance against the live private helper is a separate
post-review integration assumption and remains an activation blocker.

## C8 stabilization

The C8 pass closes four local control-plane consistency gaps without changing
public policy or activating a runtime:

- Native Latest attachment, capture, and header/model/session results carry the
  current selection generation. Delayed results from an earlier selection are
  discarded even in an A→B→A switch, while the previous native frame or a
  bounded loading surface covers a valid transition. Genuine attach failure
  still reaches the existing compatibility fallback.
- Linked-Git broker review remains explicitly row-selected, but the immutable
  context and receipt become the authority for preparation, execution, and
  recovery. Later TUI selection changes do not replace the target. Branch,
  stopped-fork posture, transaction, path, or authority drift remains
  fail-closed, and durable action receipts reconstruct commit evidence after an
  executor or UI interruption.
- Terminal reports from an assignment's caller or exact bound fork now project
  to assignment state, `last_report_id`, and report-time `completed_at`.
  Cross-campaign and cross-agent metadata is rejected, existing terminal state
  cannot be rewritten, and campaign-status readback replays persisted reports
  before applying a requested status filter. This repairs the
  persisted-report/projection crash window for both filtered and unfiltered
  restart readback.
- Targeted Joplin write sync remains independent from strict profile E2EE
  validation. The targeted lane verifies its exact note/readback and may remain
  successful while historical encrypted items keep profile validation locked.
  Both lanes survive store reopen, and retry is Agent- and target-scoped and
  reuses an already queued or running retry.

The native-transition, broker, campaign, and Joplin changes are local source
and test checkpoints only. They do not restart the daemon/TUI, access a live
Joplin profile, mutate a WorkerBee runtime, or grant new authority.

## Trusted Workbench linked Git roots

Trusted Workbench launch projection retains each canonical common Git
directory that was already qualified into the activated workspace set as an
explicit writable sandbox root. It does so even when that directory is nested
beneath an approved checkout: a more-specific read-only sandbox mount can
otherwise override the writable parent and prevent a linked worktree from
creating its per-worktree `index.lock`.

Only exact canonical duplicates are collapsed. The narrower per-worktree,
object, branch-ref, and reflog paths remain topology and broker evidence; they
are not promoted to launch roots. Review forks, non-Trusted profiles, protected
secret-file denies, and network/local-binding posture retain their existing
behavior.

## Activation and rollback

This checkpoint does not activate a daemon, TUI, backend, helper, or lease. A
reviewed package update and normal daemon/TUI restart are required before the
new readback can be used. Activation must first compare the live selected
backend catalog with the reviewed fixture and keep unknown additions
quarantined. Rollback restores the prior reviewed package and restarts Agent
PBX; durable legacy receipts continue to load through additive migration and no
WorkerBee backend or workspace is switched implicitly.

For the linked-Git projection specifically, load the reviewed TUI/package and
verify the exact common Git root before guarded same-fork resume; the daemon
does not require a source-only restart. A process that is already running does
not inherit the new mount. On qualification or readback failure, leave the fork
stopped and restore the prior TUI/package. Repository branch or ref repair is a
separate authorization and is never part of this activation or rollback.
