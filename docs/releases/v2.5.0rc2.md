# Agent PBX 2.5.0rc2

Agent PBX 2.5.0rc2 is a focused correction to the v2.5 terminal-delivery
contract. It preserves the complete v2.5.0rc1 component, WorkerBee, broker, and
managed-runtime boundaries while separating immutable workflow history from the
current ability to interact with an exact retained Codex runtime.

The candidate does not advance the database schema. Schema 45, public routes,
OpenAPI structure, Store signatures, transaction boundaries, feature defaults,
and migration behavior remain unchanged.

## Projection and readiness are independent

Campaign assignments and reports remain durable workflow history. A terminal
report can close its bound assignment and campaign, and late reports cannot
reopen or rewrite that terminal projection.

Terminal delivery now treats report-derived status as explanatory projection,
not as runtime authorization. Current interaction readiness is proven from the
exact managed target:

- entity and Codex session identity;
- dedicated tmux server, socket, session, window, and pane;
- process PID and start ticks;
- runtime mapping generation;
- workspace, workspace-set digest, and authority profile;
- a bounded terminal capture classified as the current idle composer; and
- an exact short-lived writer lease followed by a second identity/readiness
  check before injection.

This permits a separately authorized successor assignment to reach an exact
input-ready retained fork even when its immutable history ends in `done`,
`needs_input`, `blocked`, or another report state. The historical assignment is
not reopened or modified.

## Fail-closed outcomes and provenance

The existing explicit outcomes remain: `delivered`, `queued`,
`target_not_ready`, `overlay_active`, `ambiguous`, `blocked`, and
`stale_mapping`.

Delivery receipts add bounded readiness provenance: runtime source/state/time,
whether that runtime evidence is report projection only, terminal classifier
reason, and the exact target identity digest. Prompt bodies, terminal text,
reasoning, credentials, and secrets are not retained.

Current non-report runtime interruption remains `target_not_ready`. Session,
generation, process, workspace, workspace-set, authority, or tmux drift remains
`stale_mapping` or `blocked`. Startup, model, update, and thinking overlays
remain `overlay_active`; approval, safety, credential, and destructive prompts
remain blocked and are never suppressed. Explicit nohup targets alone retain
queue fallback.

## Compatibility

Existing runtime mappings that predate an explicit generation field use their
durable mapping-creation identity as the compatibility generation. A declared
generation must be a bounded string or integer; malformed or changed declared
evidence fails closed. No existing entity, campaign, report, command, runtime
mapping, or writer lease is rewritten by installation.

The correction does not grant Git staging or commit authority, change exact
broker approval, alter WorkerBee access, add provider or credential access,
broaden review forks, or introduce publication or remote-client authority.

## Isolated qualification

The RC2 fixture binds the reviewed Operator-0 terminal report, rejected
delivery, readiness report, and successful delivery receipts, plus the retained
Operator-6 analogue. Its harness uses disposable SQLite and workspace roots and
mocked tmux/process/capture/send boundaries. It verifies:

- terminal history plus an independently input-ready runtime;
- late-report immutability;
- current interruption rejection;
- exact session/process/workspace/authority/generation drift rejection;
- overlay and writer-lease rejection;
- caller-stable replay without duplicate injection; and
- zero prompt-body leakage in audit evidence.

No live managed pane, socket, daemon, TUI, mapping, or lease is used by the
harness.

## Upgrade and rollback

Run the normal doctor and migration dry-run before a separately reviewed local
activation. The expected schema-45 result is `changes_required=false`:

```bash
agent-pbx doctor
agent-pbx migrate dry-run
agent-pbx migrate backup --retention-days 7
```

Activation must separately verify the exact candidate commit/tree, daemon code
identity, schema 45, default-disabled gates, workspace roots, and every retained
managed runtime mapping. Do not restart the managed tmux server or healthy
Codex processes solely for this correction.

Source rollback selects v2.5.0rc1 commit
`3c4096c7d992612420e066eaf3b3e74ca70d919b` and tree
`0b2706fe8c2a29ecf24c1a5cb644bfe616b1412c`. An activated rollback stops only
the Agent PBX daemon, restores the reviewed prior
package/configuration identity (and database backup only if an unrelated change
made that necessary), starts the prior daemon, and re-verifies schema, gates,
roots, mappings, and health. Managed tmux sessions and Codex processes remain
untouched.

## Release boundary

This candidate remains subject to bounded nonserial and serial qualification,
documentation/static/diff checks, immutable artifact review, and a separate
root authorization for any activation, tag, push, TestPyPI/PyPI publication,
or GitHub/Gitea release. Stable v2.5.0 promotion remains held.

After a separately authorized TestPyPI publication, install the candidate with:

```bash
python -m pip install --index-url https://test.pypi.org/simple/ \
  --extra-index-url https://pypi.org/simple/ \
  agent-pbx==2.5.0rc2
```
