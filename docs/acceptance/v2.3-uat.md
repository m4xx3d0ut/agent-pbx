## Schema 30 to 32 qualification

`tests/test_migration.py` creates a private schema-30 fixture containing a
retained starred caller Agent, a retained root Operator, and a durable event.
It removes the schema-31/32 WorkerBee policy and transition tables before the
migration begins.

The qualification proves:

1. dry-run reaches schema 32 in a copied database and leaves the source at
   schema 30;
2. apply creates the three new WorkerBee tables and preserves both entities
   and the event;
3. verification reports schema 32 with SQLite integrity `ok`;
4. rollback restores schema 30, removes the new tables, and retains the Agent
   and Operator records;
5. configuration discovery and all backup artifacts remain inside `tmp_path`.

No live database copy is required for this gate, and no migration command is
run against the workstation daemon.

## Deferred live checks

Run these only after the operator selects a safe activation window:

1. back up the live schema-32 database and local configuration;
2. install or check out the exact reviewed candidate;
3. restart the daemon and TUI without restarting managed Codex panes;
4. verify Agent, root Operator, edit-fork, review-fork, tmux, WorkerBee, Joplin,
   model-elevation, and browser-demo posture;
5. record process identity, schema, model/catalog, and rollback evidence;
6. smoke a new managed Agent launch in an isolated project;
7. restore the previous package and backup if any mapping or policy check fails.

Before the smoke launch, inspect each retained pending project-spawn request.
Cancel obsolete or pre-existing-repository requests through the dedicated
cancel action; do not approve them. Callers created before this repair keep
their Codex sessions. Reconcile their mapping through the existing preview/apply
workflow, and restart/resume in place only when the caller never registered a
usable current Codex session.

The existing daemon and TUI remain the rollback source until this activation is
explicitly approved.
