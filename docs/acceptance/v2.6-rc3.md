## RC3 correction

Local RC2 activation exposed one retained-compatibility gap. The API returns
the canonical `sol-5.6-max` identity for historical `sol-max` elevation
requests, while the TUI intentionally retains the old alias for a migration
preset. The TUI compared those two strings literally while preparing or
activating an elevation transition.

RC3 resolves both aliases through the existing typed managed-profile registry
before comparison. A canonical API lease and retained preset now compare as
the same elevated profile, while an unknown or different profile still fails
closed.

The first implementation introduced a new helper in `tui.py`. The component
decomposition gate correctly rejected that growth. The final implementation
reuses the existing profile resolver and keeps `tui.py` within every reviewed
line, byte, AST-node, and function ceiling.
