## Checkpoint 1 evidence

The harness exposes `plan`, `start`, `status`, `run`, `stop`, and guarded
`purge` commands. Each run receives a private HOME/XDG tree, state database,
loopback port and token, dedicated tmux socket path, fixture integration
executables, and an atomic `0600` manifest. The manifest records source
revision/dirty state, process ID plus Linux process start ticks, exact command
runs, and cleanup status.

The real smoke run started Agent PBX 2.1.1 on a random loopback port, returned a
healthy `/healthz`, reported the same isolated daemon PID through `status`, then
stopped and purged only its task-owned run directory. No production integration
variables were inherited by the harness environment.

## Checkpoint 2 evidence

WorkerBee harness bindings now use
`agent-pbx.workerbee-harness-binding/v1`. Fixture mode creates a task-owned
workspace without contacting WorkerBee. OSS-local and platform-debug modes
stage a clean committed Git archive into the harness artifact tree, calculate a
deterministic content digest, and emit the exact project/path/digest arguments
required by `workerbee_v1_session_start`.

Platform-debug staging requires the explicit `--allow-platform-debug` flag.
Live-capable modes reject dirty source, project names outside the
`agent-pbx-harness-*` namespace, unsafe archive paths/links, and workspace drift
after receipt creation. No WorkerBee endpoint or selected host backend was
changed during qualification.

An authorized live bootstrap probe proved that the current platform-debug
endpoint also enforces a private workspace import root and correctly rejected
the harness-local `/tmp` snapshot with `WORKSPACE_BINDING_PATH_OUTSIDE_ROOT`.
The adapter therefore keeps local snapshot provenance separate from the
WorkerBee-visible path and reports `snapshot_ready_unbound` until an operator or
staging service supplies a path under that endpoint's import root. It will not
send a misleading local path to `workerbee_v1_session_start`. The endpoint does
not currently advertise its import root, so this remains an explicit staging
boundary rather than a public-repository assumption.

## Checkpoint 4 evidence

The Editor tab can now open its current clean file in an allowlisted native
terminal editor. Profiles are structured executable argument arrays loaded from
`AGENT_PBX_TERMINAL_EDITOR_PROFILES`; Agent PBX never parses an operator-provided
shell command. Neovim, Vim, and Nano are discovered as safe defaults when no
custom profiles are configured.

Each running editor receives a dedicated, task-scoped tmux server and session
under the daemon state root. Its socket, pane, and process identity are separate
from every Codex runtime mapping. Closing the embedded client or changing tabs
leaves the editor process alive, while Stop Term terminates only that editor
session and reloads the file through the normal conflict-aware Textual editor.
Daemon shutdown cleans up editor-only runtimes and does not inspect, move, or
signal Codex panes.

The service resolves files through `AgentFileService`, retaining project-root,
sensitive-file, symlink, traversal, and regular-file checks. A dirty Textual
buffer must be saved or reverted before a terminal editor starts. Plain F keys
remain PBX navigation keys; modified F keys reach the editor, and printable and
control input bypasses PBX action bindings while the terminal editor owns focus.

## Checkpoint 5 evidence

The daemon now wraps the installed WorkerBee switcher with
`agent-pbx.workerbee-switch/v1` transactions. A switch must begin with a real
`--dry-run` preview. Agent PBX records the active backend fingerprint, target,
plan digest, private preview token, expiry, and a `0600` transaction receipt.
Apply rejects expired, stale, mismatched, or unconfirmed previews; selecting
`platform_debug` also requires the explicit privileged-backend confirmation.

After apply, Agent PBX verifies both switcher provenance and the WorkerBee MCP
bootstrap capability contract. Failed verification attempts an automatic
return to the receipt's prior backend and persists whether that rollback was
verified. A verified transaction can be rolled back once through the same
controller boundary. Successful apply and rollback clear daemon and TUI
WorkerBee caches. Existing Codex sessions are reported as pinned; backend
selection applies to future sessions rather than rewriting live session tool
bindings.

The WorkerBee tab adds preview actions for OSS and platform-debug plus rollback.
Each opens a typed confirmation modal showing current/target backend and the
future-session boundary. Palette equivalents are `/workerbee switch oss`,
`/workerbee switch debug`, and `/workerbee switch rollback`.

Qualification exposed an upstream operational hazard: `wb-mcp-switch precheck`
is not observational when platform-debug is already active. It starts and
stops the named debug container, leaving the selected backend stopped. The
Agent PBX preview path deliberately does **not** invoke `precheck`; it uses the
switch command's actual `--dry-run` mode. During this qualification the prior
platform-debug backend was restored from its retained local image with the same
container name, ports, volumes, security options, and command. Final evidence
returned `platform_debug`, HTTP-ready MCP/console, MCP server `1.30.0`, and a
successful `workerbee_v1_capabilities` response for WorkerBee `0.1.7`.

## Checkpoint 6 evidence

`agent-pbx wiki check` validates the versioned `docs/wiki` source, local link
targets, required Home page, and public-source hygiene without network access.
`agent-pbx wiki stage` rewrites in-wiki links for GitHub Wiki navigation,
converts repository links to revision-pinned GitHub links, generates a stable
`_Sidebar.md`, and writes per-page SHA-256 checksums plus a deterministic tar
archive. Agent PBX refuses to replace a staging directory without its own
supported manifest.

`agent-pbx wiki publish` is a separate external action. It verifies every
staged checksum, requires `--confirm` to exactly match the reviewed stage
digest, requires an explicit remote, and restricts external remotes to
`.wiki.git`. It updates only staged Agent PBX page names and preserves unknown
remote pages. The publisher was qualified against a local bare Git wiki,
including confirmation rejection, tamper detection, initial update, and
unknown-page preservation. No GitHub Wiki clone, commit, or push occurred in
this checkpoint.

The repository wiki source passes the new checker. A review artifact is staged
under the ignored `artifacts/wiki-stage` tree; checkpoint 7 regenerates it at
the final release commit so revision-pinned links and its digest match the
2.2.0 candidate exactly.
